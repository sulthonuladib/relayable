The capability model
--------------------
The frozen EngineAdapter trait has one extra (defaulted) method:

    fn capabilities(&self) -> Capabilities

Capabilities is a plain struct of `bool` flags in src/model.rs, one per
check-expressible feature:

    title, bell, osc8_hyperlinks, bracketed_paste_mode, mouse_modes,
    mouse_sgr_flag, app_cursor_keys, alt_screen, scrollback_bound,
    reflow_on_resize, wide_glyphs, combining_chars, truecolor, indexed_256,
    per_cell_style, selection_to_string

The default is Capabilities::ALL. The alacritty_terminal 0.26.0 adapter never
overrides `capabilities()`, so its declaration carries no information beyond
that ALL default; it is the gating engine precisely so that the capability
model cannot hide anything for it. What is true is narrower than "a PASS can
never regress": the model means no check can be *suppressed* for
alacritty_terminal (no alacritty check is turned off by a capability
declaration). A PASS obviously can still regress to FAIL if the engine's real
behaviour changes, and that is exactly what the assertions are for.

Each check consults the capability set:

  * if the engine declares the required capability absent, the check is
    recorded UNSUPPORTED with the missing capability named in the artifact
    (a capability gap, never a FAIL);
  * otherwise the check runs and asserts as before.

This separates "the engine does not provide this feature" from "the engine
tried and produced the wrong state". It does not hide a wrong result: a FAIL is
still emitted when a declared-present capability is exercised and disagrees.

`selection_to_string` is wired for alacritty_terminal
(`Term::selection_to_string`, `alacritty_terminal-0.26.0/src/term/mod.rs:529`)
and vt100 (`Screen::contents_between`,
`vt100-0.16.2/src/screen.rs:167`, documented as the clipboard-selection helper).
`avt 0.18.0` has no selection-range API (`grep -rni selection avt-0.18.0/src`
is empty), so it is declared absent and the check is UNSUPPORTED. The two
implemented engines use different end-column conventions (alacritty simple
selection includes the end cell; vt100 `contents_between` is exclusive of
`end_col`), and each artifact asserts its engine's exact extracted string.

termwiz 0.23.3 is the only NOT_IMPLEMENTED stub. It has no byte-stream ->
screen-state emulator: escape::parser::Parser::parse
(src/escape/parser/mod.rs:86) only decodes into escape::Action
(src/escape/mod.rs:28) and nothing maps Action -> surface::Surface
(src/surface/mod.rs:105 has no Action reference), while
terminal::UnixTerminal::new opens /dev/tty (src/terminal/unix.rs:266) and
captures tty termios via Termios::from_fd (src/terminal/unix.rs:171). It is
reported UNSUPPORTED for every check, never PASS/FAIL.

UNSUPPORTED reasons by engine (33 checks per engine)
----------------------------------------------------
alacritty_terminal (32 PASS / 1 UNSUPPORTED):
  bracketed_paste_payload — input-path property (see below); UNSUPPORTED for
  every engine by design. No capability suppresses any alacritty check.

vt100 0.16.2 (28 PASS / 5 UNSUPPORTED):
  osc8_hyperlink, osc8_real, replay_osc8_ls — vt100 0.16.2 does not implement
  OSC 8 at all.
  resize_reflow — vt100's Grid::set_size clears row wrapping instead of
  reflowing logical lines, so there is nothing to compare.
  bracketed_paste_payload — input-path property (below).

avt 0.18.0 (17 PASS / 16 UNSUPPORTED):
  osc_title, osc_title_real — no OSC 0/2 handling (parser::osc_put is a no-op).
  bell, bell_real — no BEL action in avt's parser::Function.
  osc8_hyperlink, osc8_real, replay_osc8_ls — no OSC 8.
  mouse_modes, mouse_sgr_flag, mouse_modes_real, replay_nvim_mouse — no
  1000/1002/1003/1006 tracking; avt's DecMode only lists 1/6/7/25/1047/1048/1049.
  replay_nvim_title — no OSC title, so the title aspect of that replay cannot be
  checked.
  bracketed_paste_mode — DecMode does not list 2004.
  unicode_combining, unicode_emoji — avt stores exactly one char per cell, so
  combining marks and VS16/ZWJ sequences overwrite rather than attach.
  selection — no selection-range API (see above).
  bracketed_paste_payload — input-path property (below).

bracketed_paste split (lead's decision)
---------------------------------------
The old single `bracketed_paste` check conflated two different things. It is
now:

  bracketed_paste_mode     asserts the DECSET/DECRST 2004 h/l toggle is
                           reflected in the engine mode flag. PASS for
                           alacritty_terminal and vt100; UNSUPPORTED for avt.
  bracketed_paste_payload  UNSUPPORTED for every engine. On the OUTPUT
                           direction an emulator correctly interprets ESC bytes
                           inside ESC[200~..ESC[201~ as control sequences
                           rather than literal text; the "bytes as data"
                           guarantee is an INPUT-path property (terminal ->
                           app) owned by CORE-001 / app-side work and cannot be
                           asserted from an output-only feed.

Recorded approximations
-----------------------
  * Mouse mode mapping (neutral MouseMode has no Press vs PressRelease
    distinction). vt100 maps DECSET 9 -> MouseProtocolMode::Press and DECSET
    1000 -> MouseProtocolMode::PressRelease; both are reported as
    MouseMode::Click. 1002 -> Drag, 1003 -> Any. The same coarse mapping is the
    only one the neutral model can express, so no model widening was done.
  * Alternate-screen cursor convention (alt_screen check). DECSET 1049 clears
    and switches to the alternate screen. alacritty carries the primary cursor
    (col 3 in the fixture) into the alt grid, so its alt row0 is "   alt";
    vt100's alternate grid owns a separate cursor, so its alt row0 is "alt".
    The exact column is an engine-specific detail outside the alt-screen
    capability, so the check asserts alt-screen entry/exit, that the primary
    text is gone from the alt screen, and that the primary screen/cursor are
    restored on 1049l, and records the observed row text verbatim.
  * vt100 scrollback is asserted through the neutral leg only (retained count
    bounded/positive/<= configured bound, newest present, oldest gone). The
    exact oldest-retained-line text is alacritty window arithmetic and is
    asserted only by the alacritty-specific leg of scrollback_bound.
  * Alt-screen transition evidence in the real/replay legs is chunk-independent
    (raw-byte scan for ESC[?1049h/l plus an engine snapshot at each transition).
    The per-chunk `watch` field is renamed `alt_in_chunk_snapshots` and is not
    used as alt-screen evidence.

How to regenerate
-----------------
  cd spikes/terminal-engine-phase2
  ./scripts/run_all.sh

run_all.sh regenerates results/raw/checks/**, results/raw/streams/**,
results/raw/perf/**, summary.txt/json, and compare/matrix.{txt,json}. This
README.txt is preserved.

The `tmux_real` check was added in the final fix pass. It asserts engine state
on a real tmux session captured through the PTY on a private socket; it is PASS
for the three implemented engines and UNSUPPORTED for the termwiz stub. See the
main README.md (§5.4 multiplexers) and results/raw/streams/tmux.cleanup.txt.
