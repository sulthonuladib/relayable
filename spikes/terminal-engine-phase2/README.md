# terminal-engine phase-2 spike (TERM-002 / ADR-003)

Standalone, engine-bearing spike that supports the ADR-003 terminal-emulation
engine decision. It is a **separate workspace root** (empty `[workspace]` table)
so it can never absorb `spikes/terminal-engine/` (phase 1, read-only), the
repository root, or any `crates/**`.

## Status: phase 2 complete (engine adapters + PTY harness + 33 checks x 4 engines)

`alacritty_terminal 0.26.0` is wired end-to-end behind the frozen
`EngineAdapter` trait and is the **gating** engine. `vt100 0.16.2` and
`avt 0.18.0` are wired comparison engines behind the same trait and are
capability-gated per check. `termwiz 0.23.3` is a deliberate
`NOT_IMPLEMENTED` stub (reason below).

## How to reproduce (single entry point)

```sh
cd spikes/terminal-engine-phase2
./scripts/run_all.sh
```

That one command is the reproduction entry point. It:

1. stamps provenance (UTC, host, rustc/cargo, git HEAD/status, tool versions,
   pinned crate versions, and the deterministic `source_tree_sha256`) into
   `results/raw/run_all_meta.txt`;
2. builds the harness (`cargo build`), then runs the real-PTY captures into
   `results/raw/streams/` (`nvim_*`, `tmux`, `ls --hyperlink`, `seq 1 20000`,
   `sh printf \a`, PTY resize, unicode, application-cursor-key round trip);
3. runs `analyze --perf-only <engine>` once **per engine** so each engine's
   throughput/RSS is measured in its own process (no cross-contamination), then
   runs the main `analyze` (fixtures + phase-1 replays + checks + merged perf);
4. generates `results/raw/compare/matrix.{txt,json}` from `summary.json`;
5. runs the quality gates (`cargo fmt --check`, `cargo build`,
   `cargo clippy --all-targets`, `cargo test`) and the analyzers' self-check
   (the self-check runs inside `analyze` **before** any per-check artifact is
   written, so a violating run never emits a `STATUS=PASS` file);
6. checks the gating engine for `NOT_TESTED` (a missing capture fails the gate),
   writes its real exit code to `results/raw/run_all_exit.txt`, and prints
   `OVERALL=PASS`/`OVERALL=FAIL`.

Individual binaries can be run directly when iterating:

```sh
cargo run --bin capture -- --name x --duration-ms 1500 -- /bin/sh -c 'printf \a'
cargo run --bin analyze -- --results-dir results/raw            # full check run
cargo run --bin analyze -- --perf-only avt --results-dir results/raw  # one isolated engine
```

`analyze` flags: `--results-dir DIR`, `--repo-root DIR`, `--cols/--rows`,
`--scrollback`, `--perf-only ENGINE`, `--perf-runs N`, `--perf-mib N`,
`--no-perf`.

`results/raw/summary.txt` currently reports (33 checks per engine):

```
Tally:

  vt100:              PASS=28 UNSUPPORTED=5

```

There are no `FAIL` and no `NOT_TESTED` results on this host. The single
`alacritty_terminal` `UNSUPPORTED` is `bracketed_paste_payload`: an input-path
property (terminal -> app) that cannot be asserted from an output-only feed, so
it is `UNSUPPORTED` for every engine by design. The other `UNSUPPORTED` results
are capability gaps (an engine genuinely does not provide the feature); see
`results/raw/compare/README.txt` and each per-check artifact's `UNSUPPORTED`
reason.

Counts can move if engines/real programs change; the committed numbers above
come from the last `./scripts/run_all.sh` on this host and are regenerated by it
(never hand-written).

## `termwiz` is deliberately an unsupported stub

`termwiz 0.23.3` has no byte-stream -> screen-state emulator, so it cannot be
driven headlessly from captured PTY bytes the way `alacritty_terminal` can:

* `termwiz::escape::parser::Parser::parse` only decodes bytes into
  `escape::Action` (`termwiz-0.23.3/src/escape/parser/mod.rs:86`,
  `src/escape/mod.rs:28`), and nothing maps `Action` -> `surface::Surface`
  (`src/surface/mod.rs:105` has no `Action` reference);
* `termwiz::terminal::new_terminal` uses the platform terminal, and
  `UnixTerminal::new` opens `/dev/tty` (`src/terminal/unix.rs:266`) and captures
  the tty termios via `Termios::from_fd` (`src/terminal/unix.rs:171`), i.e. it
  needs a real tty rather than accepting a captured byte stream.

Its adapter is therefore constructible but marked `NOT_IMPLEMENTED`; every
check against it is recorded `UNSUPPORTED` (never PASS/FAIL) with this reason.

### §5.4 multiplexers: tmux (fully evidenced)

The `tmux_real` check asserts engine state on a **real tmux session captured
through the PTY**, so §5.4 multiplexer coverage is fully evidenced on this host
(not merely recorded):

* capture: `tmux -L relayable-term002-spike -f /dev/null new-session 'printf "RELAYABLE_TMUX_MARKER\n"; sleep 4'`,
  driven by `capture --duration-ms 3000`;
* the check asserts `ESC[?1049h`/`ESC[?1049l` are present in the raw bytes, that
  the engine's own `alt_screen` flag is true after the `1049h` and false after
  the `1049l`, and that the engine's alt-screen snapshot at the marker byte
  offset contains `RELAYABLE_TMUX_MARKER` while `alt_screen == true` (the marker
  is asserted mid-replay because tmux clears the screen before detaching, so the
  last alt snapshot before `1049l` is blank).

The capture uses a **private socket only** (`-L relayable-term002-spike`); the
user's default tmux server is never referenced. `scripts/run_all.sh` kills the
private server immediately after the capture and records the exact cleanup
command, its real exit code, and the real verification that no server remains
in `results/raw/streams/tmux.cleanup.txt`:

```
command=tmux -L relayable-term002-spike kill-server
kill_server_exit=0
command=tmux -L relayable-term002-spike list-sessions
verify_no_server_exit=1 (0 = a server is still running; non-zero = none)
leftover_server=none
```

If `tmux` is absent on another host the capture is skipped, `tmux_real` is
recorded `NOT_TESTED`, and `run_all.sh` treats it as a documented skip (the
gating-engine `NOT_TESTED` check only fails when a capture is missing
undocumented) — the README must then be updated to state that §5.4 coverage is
only PARTIALLY evidenced on that host.

## Evidence layout

* `results/raw/checks/*.txt` — one artifact per (engine, check): provenance,
  cited inputs with SHA-256, `EXPECTED`/`ACTUAL`/`STATUS` per assertion, screen
  dump, notes. Engine-input payloads are persisted under
  `results/raw/fixtures/engine_*.{bin,meta}` (`kind=engine-input`) so every
  cited hash is recomputable.
* `results/raw/streams/` — raw real-PTY captures (`*.bin` + `*.meta`) and the
  tmux private-socket cleanup record (`tmux.cleanup.txt`).
* `results/raw/perf/` — per-engine isolated throughput/RSS observation
  (3 passes; min/median/max and every raw pass).
* `results/raw/compare/` — generated per-check x per-engine matrix and the
  capability-model explanation.
* `results/raw/summary.{txt,json}`, `results/raw/run_all_meta.txt`,
  `results/raw/run_all_exit.txt` — tallies, provenance, real exit code.

Nothing in this spike is fabricated: every artifact comes from a real command
run on this host. `analyze` runs its self-check **before** writing any artifact
and exits non-zero (writing no per-check file) if it finds an empty/placeholder
`ACTUAL` value, a cited source file that does not exist, or a replay check with
no real engine assertion.

## Provenance: `source_tree_sha256` (the real code revision)

The phase-2 tree is **untracked** during the spike, so the `git_head:` stamp is
the **BASE commit the spike branch was cut from** (`a1091e58…`) — it is *not*
the code revision that produced an artifact. To identify the code revision
without git, every artifact and `results/raw/run_all_meta.txt` stamp a
deterministic `source_tree_sha256`:

> sha256 over the sorted, newline-joined list of
> `<relative_path>:<file_sha256>` for
> `spikes/terminal-engine-phase2/{Cargo.toml, Cargo.lock, src/**, scripts/run_all.sh}`
> (each entry is `<path>:` followed by the sha256 of that file's bytes, lines
> joined with `\n` including a trailing newline, then hashed).

Recompute it from the repository root with:

```sh
cd <repo-root>
{
  for f in \
    spikes/terminal-engine-phase2/Cargo.toml \
    spikes/terminal-engine-phase2/Cargo.lock \
    spikes/terminal-engine-phase2/scripts/run_all.sh; do
    printf '%s:%s\n' "$f" "$(sha256sum -- "$f" | cut -d' ' -f1)"
  done
  find spikes/terminal-engine-phase2/src -type f -print0 \
    | xargs -0 -r sha256sum \
    | while read -r sum path; do printf '%s:%s\n' "$path" "$sum"; done
} | LC_ALL=C sort | sha256sum | cut -d' ' -f1
```

The same value is computed in code by
`report::source_tree_sha256()` (used by the `summary` stamp and every per-check
artifact) and by the `source_tree_sha256()` shell function in
`scripts/run_all.sh`; the two implementations are byte-identical. The value for
the committed `results/raw` run is
`cc5529d4584f054e531f0a0eca4a1981b3ba0d6172f5dd5e20e4047a9a9f521d`.
